# 🎬 یوتیوب دانلودر (YouTube Downloader)

وب‌اپلیکیشن دانلود ویدئو و MP3 از یوتیوب — ساخته‌شده با **Next.js 16 (App Router)**، **PostgreSQL + Drizzle ORM**، **yt-dlp** و **ffmpeg**.

[![CI](https://github.com/AliB11/YoutubeVideoAndAudioDownloader/actions/workflows/ci.yml/badge.svg)](https://github.com/AliB11/YoutubeVideoAndAudioDownloader/actions/workflows/ci.yml)

## ✨ امکانات

| بخش | توضیح |
|---|---|
| 🎬 **دانلود ویدئو** | آدرس ویدئو را بدهید؛ تمام کیفیت‌های موجود (144p تا 4K/60fps) با حجم تقریبی لیست می‌شود و با یک کلیک به‌صورت **MP4** (ویدئو + صدا ادغام‌شده، H.264، سازگار با پخش وب) دانلود می‌شود. |
| 🎵 **دانلود MP3** | همان آدرس را بدهید؛ کیفیت‌های MP3 (**320 / 256 / 192 / 160 / 128 / 96 / 64 kbps**) لیست می‌شود و فایل MP3 همراه با کاور و متادیتا ساخته و دانلود می‌شود. |
| 📊 **پیشرفت لحظه‌ای** | نوار پیشرفت به‌همراه **سرعت دانلود و زمان باقی‌مانده** برای مراحل دانلود، ادغام ویدئو/صدا و تبدیل به MP3. |
| 🧮 **صف دانلود** | حداکثر چند دانلود هم‌زمان اجرا می‌شود (`MAX_CONCURRENT_DOWNLOADS`) و بقیه با وضعیت «در صف» و شماره‌ی نوبت نمایش داده می‌شوند تا منابع سرور اشباع نشود. |
| 🗂 **تاریخچه** | تمام دانلودها در PostgreSQL ذخیره می‌شوند (با فیلتر ویدئو/MP3) و تا زمان انقضا قابل دانلود مجدد هستند. |
| ⏹ **لغو و حذف** | دانلود در حال انجام **یا در صف** را می‌توان لغو کرد؛ حذف رکورد هم با تأیید دو مرحله‌ای انجام می‌شود. |
| ⬇ **دانلود قابل ادامه** | پشتیبانی از `Range` (Resume در دانلود منیجرها) و درخواست `HEAD`. |
| 🔍 **خطاهای فارسی و راهنما** | خطاهای رایج yt-dlp (ربات‌بودن، ویدئوی خصوصی، محدودیت منطقه‌ای، پخش زنده، خطای شبکه…) به پیام فارسی همراه با راه‌حل تبدیل می‌شوند. |
| 🩺 **وضعیت سامانه** | نمایش زنده‌ی وضعیت yt-dlp، ffmpeg، دیتابیس و صف در پایین صفحه (از `GET /api/health`). |
| 🧹 **پاک‌سازی خودکار** | فایل‌های موقت پس از مدت مشخص (پیش‌فرض ۲ ساعت) از سرور حذف می‌شوند. |
| 🧪 **آزمون خودکار** | آزمون‌های واحد (`npm test`) و آزمون دود سرتاسری (`npm run smoke`) + بررسی lint/typecheck/build در CI. |
| 🌐 **فارسی و RTL** | رابط کاربری کاملاً فارسی با فونت وزیرمتن (self-host)، اعداد فارسی، دسترس‌پذیری (ARIA) و احترام به `prefers-reduced-motion`. |
| 🪟 **بسته‌ی ویندوز** | نصب‌کننده‌ی `.exe` (بدون دسترسی مدیر) و نسخه‌ی Portable — همراه Node.js، yt-dlp و ffmpeg؛ میانبر منوی استارت و اجرای خودکار. جزئیات: `packaging/windows/`. |
| 🎨 **حالت نمایشی** | با `DEMO_MODE=1` می‌توان بدون دسترسی به یوتیوب، کل جریان (دانلود واقعی از کلیپ نمونه + پیشرفت + تبدیل) را نمایش داد. |
| 🔌 **بدون دیتابیس هم کار می‌کند** | اگر `DATABASE_URL` تنظیم نشود، دانلود و تبدیل همچنان فعال است؛ فقط تاریخچه‌ی ماندگار ذخیره نمی‌شود. |

> ⚠️ این ابزار برای دانلود محتوایی است که حق استفاده از آن را دارید (ویدئوهای خودتان، محتوای با مجوز Creative Commons و…). لطفاً به حقوق پدیدآورندگان و قوانین یوتیوب احترام بگذارید.

## 🚀 اجرا با Docker (پیشنهادی)

```bash
git clone https://github.com/AliB11/YoutubeVideoAndAudioDownloader.git
cd YoutubeVideoAndAudioDownloader
docker compose up -d --build
```

سپس به `http://localhost:3000` بروید. دیتابیس، yt-dlp و ffmpeg همه داخل کانتینر آماده‌اند و سرور با کاربر غیر‌روت (`appuser`) اجرا می‌شود. سلامت سرویس هم با `HEALTHCHECK` روی `/api/health` بررسی می‌گردد.


## 🪟 نصب روی ویندوز (بدون نیاز به Node.js و بدون دانش فنی)

نصب‌کننده‌ی آماده‌ی ویندوز (`.exe`) در صفحه‌ی
[Releases](https://github.com/AliB11/YoutubeVideoAndAudioDownloader/releases) قرار می‌گیرد:

1. فایل `YouTubeDownloader-Setup-<version>-x64.exe` را دانلود و اجرا کنید
   (نصب برای کاربر جاری است و **به دسترسی مدیر نیازی ندارد**).
2. از منوی استارت «یوتیوب دانلودر» را اجرا کنید؛ یک پنجره‌ی سرویس باز می‌ماند و
   مرورگر خودکار روی `http://127.0.0.1:3000` باز می‌شود.
3. برای بستن، همان پنجره را ببندید یا `Stop-YouTubeDownloader.cmd` را اجرا کنید.

نسخه‌ی **Portable** (`YouTubeDownloader-Portable-<version>-x64.zip`) هم موجود است: فایل را
از حالت فشرده خارج کنید و `Start-YouTubeDownloader.cmd` را اجرا کنید — بدون هیچ نصبی.

بسته‌ی ویندوز شامل Node.js، yt-dlp و ffmpeg است (کاربر نهایی به هیچ پیش‌نیازی نیاز ندارد)،
تنظیمات از فایل `.env` کنار برنامه خوانده می‌شود و فایل‌ها/لاگ‌ها در پوشه‌ی `data\` قرار می‌گیرند.
برای به‌روزرسانی yt-dlp (در صورت تغییرات یوتیوب) فایل `Update-yt-dlp.cmd` را اجرا کنید.

### ساخت خودتان

```powershell
# روی ویندوز (نیاز به Node.js 20+ و Inno Setup 6 برای ساخت فایل نصب)
powershell -ExecutionPolicy Bypass -File packaging\windows\build.ps1 -Version 1.0.0 -AutoInstallInno
```

یا بدون ویندوز: تب **Actions → Windows package → Run workflow** بسته را روی رانر ویندوزی
گیت‌هاب می‌سازد (Artifacts) و با push تگ `v*` (مثل `v1.0.0`) خودکار در Releases منتشر می‌کند.
جزئیات کامل در [`packaging/windows/README.md`](packaging/windows/README.md) آمده است.

## 🛠 اجرای محلی (بدون Docker)

پیش‌نیاز: Node.js 20+ (PostgreSQL اختیاری است — فقط برای تاریخچه)

```bash
cp .env.example .env         # DATABASE_URL را تنظیم کنید (اختیاری)
npm install
npx drizzle-kit push         # ساخت جدول‌ها (فقط اگر دیتابیس دارید)
npm run dev                  # http://localhost:3000
```

- **yt-dlp**: در اولین درخواست به‌صورت خودکار از ریلیز رسمی GitHub دانلود و در پوشه `.bin/` ذخیره می‌شود (یا `YTDLP_PATH` را تنظیم کنید).
- **ffmpeg**: از پکیج `ffmpeg-static` استفاده می‌شود (یا `FFMPEG_PATH` را تنظیم کنید).
- اگر از باینری نصب‌شده با pip استفاده می‌کنید، اپلیکیشن به‌صورت خودکار `--remote-components ejs:github` را اضافه می‌کند تا حل چالش جاوااسکریپت یوتیوب کار کند (باینری رسمی این ماژول را همراه دارد).

### بیلد production

```bash
npm run build
npm run start
```

## 🧪 آزمون‌ها

```bash
npm test          # آزمون‌های واحد (پارسر پیشرفت، نام فایل، بازه‌ی Range، آرگومان‌های yt-dlp، ترجمه‌ی خطا)
npm run lint      # ESLint
npm run typecheck # بررسی تایپ‌ها
npm run build     # بیلد کامل
```

آزمون دود سرتاسری (نیازمند yt-dlp و ffmpeg و اجرای سرور در حالت نمایشی):

```bash
# پنجره‌ی اول
DEMO_MODE=1 npm run dev

# پنجره‌ی دوم
npm run smoke
```

این آزمون مسیر کامل را بررسی می‌کند: سلامت سامانه → دریافت اطلاعات → ساخت job → پیشرفت زنده (سرعت/ETA) → تکمیل MP4 و MP3 → پاسخ `HEAD` و `Range` → جلوگیری از دانلود تکراری → لغو و حذف.

## 🎨 حالت نمایشی (DEMO_MODE)

در محیط‌هایی که سرور به یوتیوب دسترسی ندارد (یا برای دموی طراحی)، با تنظیم `DEMO_MODE=1`:

1. اطلاعات ویدئو از داده‌ی نمونه خوانده می‌شود (بدون درخواست به یوتیوب).
2. دانلود از یک **کلیپ نمونه‌ی محلی** انجام می‌شود که خود اپلیکیشن با ffmpeg می‌سازد و در `GET /api/demo/media` سرو می‌کند.
3. yt-dlp، پیشرفت لحظه‌ای، ادغام/تبدیل با ffmpeg و تحویل فایل به مرورگر **کاملاً واقعی** اجرا می‌شوند (سرعت دانلود برای دیده‌شدن نوار پیشرفت محدود می‌شود؛ با `DEMO_LIMIT_RATE=0` می‌توان غیرفعالش کرد).

در این حالت یک نوار آبی «حالت نمایشی فعال است» در بالای صفحه نمایش داده می‌شود تا با محیط واقعی اشتباه نشود.

## ☁️ استقرار (Deploy)

اپلیکیشن به یک **سرور** نیاز دارد (اجرای yt-dlp/ffmpeg در پس‌زمینه)، پس روی هاست استاتیک اجرا نمی‌شود:

- **هر VPS / سرور مجازی با داکر:** `git clone` + `docker compose up -d --build` (ساده‌ترین).
- **Railway / Render / Fly.io:** سرویس «Dockerfile» بسازید و `DATABASE_URL` را ست کنید.
- **بدون دیتابیس هم بالا می‌آید:** فقط تاریخچه ذخیره نمی‌شود.

> برای استقرار عمومی، یک لایه‌ی احراز هویت (Basic Auth یا Reverse Proxy) جلوی اپلیکیشن بگذارید. محدودکننده‌ی نرخ داخلی (`RATE_LIMIT_PER_MINUTE`) فقط از سوءاستفاده‌ی ساده جلوگیری می‌کند.

## ⚙️ متغیرهای محیطی

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `DATABASE_URL` | — | رشته اتصال PostgreSQL (اختیاری؛ بدون آن تاریخچه ذخیره نمی‌شود) |
| `YTDLP_PATH` | دانلود خودکار | مسیر باینری yt-dlp |
| `FFMPEG_PATH` | `ffmpeg-static` | مسیر ffmpeg |
| `YTDLP_CACHE_DIR` | `/tmp/yt-dlp-cache` | پوشه کش yt-dlp |
| `YTDLP_COOKIES_FILE` | — | فایل کوکی (Netscape) برای عبور از «Sign in to confirm you're not a bot» |
| `YTDLP_PROXY` | — | پراکسی، مثلاً `socks5://127.0.0.1:1080` |
| `YTDLP_EXTRA_ARGS` | — | آرگومان‌های اضافی yt-dlp |
| `YTDLP_REMOTE_COMPONENTS` | خودکار | ماژول حل چالش JS (برای باینری pip به‌صورت خودکار `ejs:github`) |
| `DOWNLOAD_DIR` | `/tmp/yt-downloader-jobs` | محل نگهداری فایل‌های دانلودشده |
| `FILE_TTL_MINUTES` | `120` | مدت نگهداری فایل‌ها روی سرور |
| `MAX_CONCURRENT_DOWNLOADS` | `3` | حداکثر دانلود هم‌زمان (بقیه در صف) |
| `RATE_LIMIT_PER_MINUTE` | `30` | سقف درخواست هر IP در دقیقه برای `info`/`jobs` (۰ = بدون محدودیت) |
| `INFO_CACHE_TTL_MS` | `300000` | مدت اعتبار کش اطلاعات ویدئو |
| `YTDLP_INFO_TIMEOUT_MS` | `120000` | حداکثر زمان استخراج اطلاعات ویدئو |
| `DB_POOL_MAX` | `5` | حداکثر اتصال‌های دیتابیس |
| `DEMO_MODE` | `0` | اجرای حالت نمایشی با کلیپ نمونه |
| `DEMO_LIMIT_RATE` | `1500K` | محدودیت سرعت دانلود در حالت نمایشی (۰ = بدون محدودیت) |
| `DEMO_MEDIA_BASE_URL` | `http://127.0.0.1:PORT` | آدرس پایه برای دانلود کلیپ نمونه |
| `NEXT_PUBLIC_SITE_URL` | `http://localhost:3000` | آدرس عمومی سایت (متادیتا، robots، sitemap) |

### 🔑 رفع خطای «Sign in to confirm you're not a bot»

یوتیوب گاهی IP سرورها را محدود می‌کند. راه‌حل:

1. افزونه‌ی *Get cookies.txt LOCALLY* را روی مرورگر نصب کنید و در حالی که وارد یوتیوب هستید، کوکی‌ها را export کنید.
2. فایل را کنار پروژه بگذارید و `YTDLP_COOKIES_FILE=/app/cookies.txt` را تنظیم کنید (در `docker-compose.yml` خطوط مربوطه را از حالت کامنت خارج کنید).

### جریان کار

1. کاربر لینک را وارد می‌کند → `POST /api/info` → yt-dlp فرمت‌ها را می‌خواند، کیفیت‌ها گروه‌بندی و کش می‌شوند (کش ۵ دقیقه‌ای).
2. کاربر کیفیت را انتخاب می‌کند → `POST /api/jobs` → اگر ظرفیت آزاد باشد دانلود شروع می‌شود، وگرنه job با وضعیت «در صف» ثبت می‌شود (دانلود تکراری همان ویدئو/کیفیت دوباره ساخته نمی‌شود).
3. کلاینت با یک اینتروال پایدار (۱ ثانیه) `GET /api/jobs/:id` را برای jobهای فعال poll می‌کند و پیشرفت/سرعت/ETA را نشان می‌دهد.
4. پس از اتمام، مرورگر خودکار `GET /api/jobs/:id/file` را باز می‌کند و فایل ذخیره می‌شود.
5. `DELETE /api/jobs/:id?cancel=1` دانلود در حال اجرا (کل گروه فرایند، شامل ffmpeg) یا job در صف را متوقف می‌کند؛ `DELETE /api/jobs/:id` رکورد را کامل از تاریخچه حذف می‌کند.
6. jobهایی که پیش از ری‌استارت سرور نیمه‌کاره مانده‌اند در اولین اجرا به‌صورت «خطا» علامت می‌خورند تا در وضعیت «در حال دانلود» گیر نکنند.

### وضعیت‌های job

`pending` (در صف) → `downloading` → `processing` (ادغام/تبدیل) → `done` | `error` | `cancelled` | `expired`
